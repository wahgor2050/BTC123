## 0. 呢個候選誠實咁講係測緊乜

研究 `research/funding_extreme_timing_btc.py`(已獨立審核)發現:Kraken 永續合約資金費率
嘅極端負值(z ≤ −2)之後,BTC 短期有真實嘅升勢資訊 ——

| 成本假設 | CAGR | 意思 |
|---|---|---|
| 真實 taker(10bp 費+5bp 滑價) | **−12.6%** | 照市價單做會蝕錢 |
| 限價 maker(2bp 費、0 滑價、**假設 100% 成交**) | **+9.3%** | 如果每張限價單都接到貨就賺 |
| 零成本 | **+13.1%**(贏 random control +1.75) | 訊號資訊本身係真,唔係雜訊 |

**冇任何 backtest 模擬過真實嘅「成交/唔成交」風險** —— 歷史低位話到你知限價「事後睇會掂到」,
但答唔到 order book 深度、排隊位置嗰啲嘢。呢個前向候選係第一次認真測呢條空隙:
**喺訊號時刻掛一張限價單,實際成交率夠唔夠高、價夠唔夠好,令盤數計得掂?**
就算係咁,呢度都仲係紙上:K 線低位掂到價就當成交,現實仲有排隊同深度風險(見 §6 偏差聲明)。
所以呢個候選嘅身份係「執行假說測試」,唔係「已驗證策略重新出擊」,任何時候都唔准叫佢做 validated。

## 1. 訊號(照抄研究原文,一隻字都唔改)

- 訊號源:Kraken Futures 永續 `PF_XBTUSD` 資金費率,**每小時結算(24 次/日,硬 assert)**。
  經 `btc_basis.fetch_funding()` 攞,但 **sources 釘死淨係 Kraken** —— 唔准用佢預設嘅
  「邊個歷史長用邊個」fallback(換咗 8 小時結算嘅 venue,168 個結算窗口會由 7 日變 56 日,
  即係另一個策略)。
- z_k = (rate_k − mean(rate_{k−168..k−1})) / samplestd(rate_{k−168..k−1});trailing 168 個
  結算、窗口尾喺 k−1、永遠唔包自己;唔夠 168 個真實觀察 → z = None;窗口 std < 1e-12 → None。
- K 線映射:某支 K 線讀到嘅 z = **佢開市時間戳或之前**最新一個結算嘅 z(同研究一樣,
  唔准因為 live 攞得到更新就偷快 —— 偷快 = 另一個策略);最新結算距 K 線開市 > 6 小時
  → 訊號 None。
- 規則(long/flat only):z ≤ **−2.0** 入市訊號;z ≥ **0.0** 出市;中間黏住唔郁。

## 2. 入市執行 —— 真正新嘢,即係個實驗本身

觸發條件(全部同時成立先落 resting order):

1. 最新一支**已收**小時 K 線嘅 z ≤ −2.0;
2. 觀察時刻距該 K 線收市 ≤ 20 分鐘(`ENTRY_DEADLINE_SEC`,同 A/B 一致;遲過就記 missed,
   唔准用歷史價補做);
3. 戶口 flat、冇 resting order、冇 pause、同一 run 內未平過倉(no_same_run_reentry,跟 B);
4. 有可用 Bitstamp 報價。

動作:**喺當時 Bitstamp best bid 掛一張限價買單**,
`qty = cash ÷ (limit_px × (1 + 0.0002))`(全倉 full/flat,同研究一樣冇 vol-target),
**限時 4 小時**(deadline = 掛單時刻 + 14,400 秒)。

**點解係 4 小時(凍結理由)**:出市訊號係 z 回到 0,squeeze 反彈通常以小時計;4 小時
= 4 個資金費率結算週期,俾張被動單一個真實機會,又唔會長到「入市嘗試」靜靜雞變成
另一個策略。以每小時 K 線計,4 小時牆鐘 ≡ **3 至 4 支完整喺窗口內嘅 K 線**(cron 喺
每小時第 7 分鐘行,實際通常係 3 支)。

成交判定(每小時 run 檢查,完全由 K 線時間戳決定,唔靠牆鐘,漏 run 唔會整走成交):

- 合資格 K 線 = 開市 ≥ 掛單時刻 **且** 收市 ≤ deadline 嘅已收 K 線(**掛單嗰陣行到一半
  嗰支 K 線唔算** —— 佢個低位可能喺掛單之前發生,當佢成交就係老作)。
- 由早到晚逐支處理:
  1. 先睇取消:該 K 線映射到嘅 z ≥ 0(或者訊號過期 None)→ **取消唔成交**
     (z 喺 K 線開市已知,低位掂價喺 K 線途中先發生,所以取消行先係因果正確嘅 tie-break),
     記 `cancelled_z_reverted`;
  2. 再睇成交:該 K 線 **low ≤ limit price** → 以 limit price 成交,費用 = **2bp maker fee**
     (跟 `funding_extreme_timing_btc_limitorder_sensitivity.py` 一模一樣),零滑價;
  3. 都唔係 → 落下一支。
- 而家時間 ≥ deadline 而所有合資格 K 線都檢查完冇成交冇取消 → 記 `expired_unfilled`,
  訂單消失。合資格 K 線因數據缺口攞唔到 → 一樣過期,唔准老作成交,data_status 記低。
- **永遠唔會老作成交** —— 同 A/B 一致嘅紀律。

重掛規則(凍結):resting 期間唔 re-peg、唔追價;過期/取消之後,要**再有一支新鮮 K 線
z ≤ −2.0** 先開新嘗試(−2 < z < 0 嘅「研究上想持倉」區域唔准用市價追入,追入 = 另一個策略)。
resting 期間再出現 z ≤ −2 嘅 K 線,記 `rejected / order_already_resting`,唔動作。

Pause 規則(凍結):`--pause` 會**取消現有 resting order**(記 `cancelled_paused`)並封鎖新掛單;
持倉出市完全唔受影響。

## 3. 出市執行 —— 照 A/B 嘅 taker 模型,唔係限價

**限價單問題喺呢個設計淨係應用喺入市**;出市係標準市價式成交:z ≥ 0(或訊號過期)嘅已收
K 線出現 → 即 run 用新鮮報價賣出,`sell = min(bid, mid × 0.9998)`、費用每邊 0.1%
(10bp,同 A/B 完全一樣嘅 taker 模型),遲到照做並記低遲到秒數;冇報價就記 `exit_unresolved`
下個 run 再試 —— 全部跟 A/B 現行紀律。**唔好誤會呢個係對稱限價策略 —— 佢唔係。**
(入市 maker 2bp、出市 taker 10bp+spread 呢個唔對稱係故意嘅:實驗焦點係「入市時刻接唔接到貨」,
出市用最保守嘅成本假設,令結果唔會靠出市優惠沖靚。)

## 4. 訊號數據中斷規則(凍結,一條規則冇窿)

state 入面持續記住**最後一次成功讀到嘅最新結算時間戳**。任何時刻嘅「訊號過期」判斷
= 最新已收 K 線開市時間 − 呢個最後已知結算時間 > 6 小時,**唔理今次 fetch 成唔成功**:

- Kraken fetch 失敗但最後已知結算仲喺 6 小時內 → 今次唔做入市決定(記 missed /
  `no_funding_data`),持倉照揸,健康警報 `no_funding` 按連續兩 run 規則發;
- fetch 失敗/成功都好,最後已知結算舊過 6 小時 → 持倉**強制出市**(`signal_stale_exit`)——
  同研究「冇可讀訊號 → flat,唔准盲揸」完全一致;連續 fetch 失敗 6 小時後自動收斂到
  呢條,冇「盲揸到永遠」嘅窿。
- fetch 成功但結算數 < 169 或者 per_day ≠ 24 → 當 fetch 失敗處理(訊號源異常,唔准將就用)。

  `diag_fill_price/diag_fee` 照舊機械式計(10bp+2bp 對 mid),但對盤中限價成交嚟講
  只係形式上嘅對照,解讀要小心。

## 6. 成交模型嘅兩個方向偏差(預先聲明,唔准事後先認)

1. **偏樂觀**:「K 線 low 掂到 limit 價就當成交」忽略咗排隊位置同深度 —— 現實入面
   low 啱啱掂到你個價,你好可能排喺隊尾接唔到。呢個係紙上測試繞唔開嘅上限偏差。
2. **偏保守**:掛單嗰陣行到一半嘅 K 線被整支剔走,佢後半段嘅真實觸價機會被放棄;
   量度到嘅成交率係**下限**。

兩個方向都寫低咗,將來讀數唔准淨係引對自己有利嗰邊。

## 7. 同研究 want-array 嘅已知分歧(呢個分歧就係實驗)

研究 backtest 入面,z 一掂 −2 就即刻「持倉」直到 z ≥ 0;前向呢度,張限價單可以完全接唔到貨
(expired_unfilled),之後 −2 < z < 0 期間唔准追入 —— 所以前向持倉軌跡會同研究 want-array
出現分歧。**呢啲 missed episode 唔係 bug,係實驗要量度嘅主體**:成交率、接到貨嗰啲 vs
接唔到貨嗰啲嘅事後表現,全部喺檢討報告披露。
